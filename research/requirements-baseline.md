# Requirements baseline (frozen 2026-11-18)

Frozen before major work. Every value below is taken from the tree at
`025ef24`; anything not established there is marked `UNRESOLVED` or `TARGET`
rather than assumed. Changing a frozen item requires an owner decision recorded
in `interventions.csv`.

## 1. Product behaviour

Residential home-automation node SoC. On-chip: RV32IM core, boot ROM, TCM,
SRAM, AXI4-Lite fabric, APB peripherals, interrupt controller, watchdog, JTAG
TAP. Off-chip host (Home Assistant) and voice assistant are out of scope.

Required peripherals (from `rtl/rtl_top/has_soc.sv`, `has_addr_map.sv`):
GPIO 16-bit, UART0/UART1, I²C master, SPI master, PWM 4-channel, timer,
watchdog, I²S, power manager, QSPI flash controller, debug JTAG TAP.

## 2. ISA and privileged behaviour

- RV32IM. Machine mode only. **No C extension, no user mode, no PMP**
  (`rtl/rtl_top/riscv_core.sv` header; stated in the block diagram).
- Synchronous traps for the implemented exception set; `minstret` counts
  retirements only; misaligned `LHU`/`LH`/`LB` trapped.
- `rresp`/`bresp` are not consumed by the core (recorded limitation).

## 3. Clock, reset, power

- Core clock: **50 MHz target**. This is a documented target; no timing closure
  exists (see G2/G3 status in `acceptance-gates.md`).
- Reset: asynchronous active-low `presetn`, synchronous release; watchdog
  produces a 16-cycle reset pulse.
- Power states: reset_ctrl clock gating, sleep, deep-sleep gating documented;
  **deep-sleep gating unproven** (listed NOT YET in the generated block diagram).
- Operating conditions for evidence: sky130 `tt_025C_1v80` (only corner used).

## 4. Address map (from `rtl/rtl_top/has_addr_map.sv`)

| Region | Base | Size |
|---|---|---|
| Boot ROM | `0x0000_0000` | 16 KB |
| TCM | `0x0001_0000` | 32 KB |
| SRAM | `0x2000_0000` | 128 KB |
| QSPI flash | `0x4000_0000` | 64 MB |
| APB peripherals | `0x5000_0000` | 1 MB |
| CLINT / PLIC | `0x8000_0000` / `0x8000_1000` | 64 KB |

Access width 32-bit; APB slots 9 × 4 KB, one-hot decode. Out-of-range access
faults in the core. ROM/SRAM *allocation* versus these declared sizes is an
open finding (`findings.csv` F5) because the memories are inferred `$mem_v2`
with no implementation inventory.

## 5. Bus

AXI4-Lite, one master × six slaves, single outstanding transaction; AXI→APB
bridge; `req_gnt_to_axi_lite` adapter. No burst support.

## 6. Boot and firmware model

Boot ROM → firmware in TCM/SRAM. Two firmware flavours exist: assembly under
`sim/asm/` and a C bare-metal build under `firmware/bare_metal/` driven by
`scripts/fw_build/build_fw.js` (images regenerated by `gen_fw_mem.js`, both
using shared discovery in `scripts/fw_build/toolchain.js`). Secure boot and OTA
signing are **not implemented**.

## 7. I/O electrical requirements

QFN-64 pinout documented in `docs/architecture/EXTERNAL_INTERFACE_AND_PINOUT.md`
and `constraints/pin_assignment_qfn64.csv`. Pad ring, drive strengths, ESD and
level compatibility are **UNRESOLVED** — no pad frame exists in the flow.

## 8. Implementation boundary

- **Full chip**, QFN-64, sky130, as instantiated by `rtl/rtl_top/has_soc.sv`.
- Not a hardened macro, not a peripheral subset. Any reduction is a scope
  change requiring an owner decision.

## 9. Process, libraries, memory

- Process: SkyWater 130 nm (`sky130`), `sky130_fd_sc_hd` standard cells.
- Library used for evidence: `build/asic_evidence/sky130_full_subset.lib`
  (subset; its `ff` blocks are incomplete for some cells — see F3).
- Memory strategy: **UNRESOLVED**. Boot ROM, TCM and SRAM remain inferred
  `$mem_v2`; no ≥64 KB macro exists in the verified subset (TD-006).
- PDK provisioning: not volare-enabled, so no OpenLane 2 flow has executed.

## 10. Acceptance criteria

Physical, verification and handoff criteria are frozen in
`acceptance-gates.md` (G0–G4). The independent-review criterion is currently
unsatisfiable in this environment and stays open; results are labelled
SELF-EVALUATED.
