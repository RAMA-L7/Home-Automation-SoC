## Verdict

**PASS for the model-fidelity claim; F3 is FIXED.**

The stub was wrong: `dfrbp` captured on the falling edge. Every authoritative
description in reach says rising edge with an asynchronous active-low clear. The
model now matches, is proven by directed vectors, and the preserved pre-fix model
fails those vectors.

**Scope limit, stated up front:** the mapper never emits `dfrbp`, and no netlist
in this repository instantiates it (0 occurrences in 72 files). The defect was
**latent** — it invalidated no previously reported result, and this run proves the
*model*, not a mapped netlist that uses the cell.

## Authoritative definition

### 1. Liberty shipped with the library (in-tree)

`build/asic_evidence/sky130_tt.lib`, `library ("sky130_fd_sc_hd__tt_025C_1v80")`,
sha256 `ec0e1067a35c8bf20b11e58d1e8ac53326067e4dac84a125cc1b917a3518d0d9`,
cell block starting line 51314 (`dfrbp_1`) and 51801 (`dfrbp_2`):

```
ff ("IQ","IQ_N") {
    clear : "!RESET_B";
    clocked_on : "CLK";
    next_state : "D";
}
```

- `clocked_on : "CLK"` — no `!`/`~` prefix, i.e. the **rising** edge. Timing arcs
  agree: `CLK -> Q` and `CLK -> Q_N` have `timing_type : "rising_edge"` (2 arcs),
  `RESET_B -> Q` is `"clear"`. There is **no** `falling_edge` arc in either cell.
- `clear : "!RESET_B"` — **asynchronous, active low**.
- `dfrbp_1` and `dfrbp_2` differ only in drive strength; their `ff` blocks are
  identical.

## Correction to the earlier F3 evidence

The prior finding text claimed `sky130_full_subset.lib` "omits the
ff/clocked_on block for dfrbp_1 (only 11 cells in that file declare
clocked_on)". **That was wrong.** The subset library has `dfrbp_1` at line 1587
and `dfrbp_2` at 2074, each with a complete `ff` block, byte-identical to the
full liberty (runner step "subset ff block matches full liberty"). The earlier
note came from counting `clocked_on` occurrences (11) and concluding they were
missing, instead of opening the cell. The reference was available all along; the
record is corrected here and in `REVIEW_LOG.md` (R-06).

## The defect and the fix

`build/asic_evidence/arith_work/sky130_stub.v`, both `dfrbp` modules:

```diff
-// dfrbp_*: negedge CLK, asynchronous active-low reset, complementary output.
+// dfrbp_*: posedge CLK, asynchronous active-low reset, complementary output.
+// Liberty (sky130_tt.lib): ff ("IQ","IQ_N") { clear : "!RESET_B";
+//   clocked_on : "CLK"; next_state : "D"; }, CLK->Q timing_type rising_edge.
+// F3: this model previously used negedge CLK; see research/runs/RUN-0008.
...
-  always @(negedge CLK or negedge RESET_B)
+  always @(posedge CLK or negedge RESET_B)
```

Nothing else changed: pins, Q_N, reset polarity and the other ten models were
already correct. Pre-fix file preserved at
`asic/synthesis/techmap/dfrbp_model/sky130_stub_prefix.v`
(sha256 `78f7268eef9b8254adf6e840a2f34313078f8f21705d7d68ab7a4a1cb9e53108`).

## Test and negative control

`asic/synthesis/techmap/dfrbp_model/tb_dfrbp_model.v` (sha256
`62d163f2…`) instantiates `dfrbp_1` **and** `dfrbp_2` and runs 11 directed checks
with literal expected values — the bench is not derived from the model:

async clear → clear dominates D → reset release is not a capture → rising edge
captures 1 → **falling edge must not capture** → rising edge captures 0 → async
clear with CLK low → release → rising edge after reset → **second falling edge

"capture" checks at the wrong time and only these two expose it.
